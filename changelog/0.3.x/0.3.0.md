# 0.3.0 — 2026-11-21

## Added

- **`ref_unicode_lookup`** ([#28](https://github.com/cyanheads/reference-data-mcp-server/issues/28)) identifies every code point in a string, or looks up code points written as `U+XXXX`, `0xXXXX`, `\u{XXXX}`, bare hex, or decimal. Each record carries name or label and aliases, category, block, script, whitespace, default-ignorable, bidi-control, and invisible flags, UTF-8 and UTF-16 encodings, NFC/NFD/NFKC/NFKD forms, and grapheme cluster; the summary indexes every invisible and bidi-control code point. `query` holds up to 4,096 code points; `limit` defaults to 32, and a value above 128 returns 128 with a notice. Data is the Unicode Character Database 18.0.0, bundled with its Unicode License V3 notice in `NOTICE` (shipped in the npm package and the image).
- **`ref_unit_convert`** accepts `mph`, `mi/h`, and `kph` ([#40](https://github.com/cyanheads/reference-data-mcp-server/issues/40)); `from_unit` and `to_unit` echo the spelling sent.

## Changed

- **Breaking: the city name `Rishon LeTsiyyon` no longer resolves.** `ref_timezone_lookup` answers `no_match` and `ref_timezone_convert` answers `invalid_timezone`, where 0.2.0 returned `Asia/Jerusalem`: `@vvo/tzdb` ^6.201.1 → ^6.204.0 lists `Petaẖ Tiqva` among that zone's main cities in its place. `Asia/Jerusalem` resolves as before.
- **Resources** percent-decode each template variable once before validation (`createApp({ decodeResourceParams: true })`), and the timezone resource no longer decodes on its own. An ID carrying a malformed percent escape is rejected with `-32007` on all three resources, element IDs made of a number followed by one (`ref://elements/1%`) included. Each resource declares typed failure reasons.
- **`ref_unit_convert`** `unknown_unit` recovery names one working spelling for each measure the description lists, and its message carries only the unit.
- **Development tooling** syncs framework skills, devcheck, packaging lint, the release script, and the changelog template to mcp-ts-core 0.13.22; the Bun test run uses the `threads` pool.

## Fixed

- **`ref_timezone_lookup` and `ref_timezone_convert`** resolve IANA location names written with spaces, hyphens, or periods (`New York`, `St. Lucia`, `Port au Prince`) and unaccented spellings of accented @vvo/tzdb cities (`Izmir`) ([#42](https://github.com/cyanheads/reference-data-mcp-server/issues/42)). The `"NY"` example, which never resolved, is removed from the tool description and the docs.
- **`ref_timezone_lookup`** `by` description states what each mode does: `iana` runs the IANA ID, city, and location-name matching without the country-code step, where it was described as an exact IANA ID match.
- **Resources** read percent-encoded country codes and atomic numbers (`ref://countries/%55S`, `ref://elements/%37%34`), which 0.2.0 answered as not found.
- **`ref_unit_convert`** returns a result that fits a double where convert-units overflowed on the way (`1e308 km` to `mi`) instead of an internal error; a result beyond a double fails with `result_out_of_range`.
